## Moonlight's preferences: three things were wrong, fixed in f637c59

```
$ ls ~/Library/Preferences | grep -i moonlight
com.moonlight-stream.Moonlight.plist
unity.DigitalSunGames.Moonlighter.plist
```

1. **The wrong file was read.** Before Moonlight was installed, the only
   match was the second one: a game called *Moonlighter*. The sort preferred
   `moonlight-stream` but never excluded anything, so `knownHosts()` returned
   `ok: true` with no hosts. The silent empty list, exactly. Now only
   `com.moonlight-stream.*` is accepted, and the file does not exist until
   Moonlight has been opened once, which the reason now says.
2. **`plutil -convert json` refuses the real file**: "Invalid object in plist
   for JSON format". `certificate`, `key`, and every host's `srvcert` and `mac`
   are `<data>`. It now converts to `xml1` and reads that with
   `packages/core/plist-xml.js` (no dependency). `<data>` becomes a Buffer.
3. **Keys are joined by dots on macOS, not slashes**, and every address has
   its own port. A real unpaired host, addresses elided:

```
hosts.2.customname     false
hosts.2.hostname       omarchy
hosts.2.ipv6address    ''
hosts.2.ipv6port       0
hosts.2.localaddress   <LAN address>
hosts.2.localport      47989
hosts.2.mac            <data, empty>
hosts.2.manualaddress  ''
hosts.2.manualport     0
hosts.2.nvidiasw       false
hosts.2.remoteaddress  <public address>
hosts.2.remoteport     47989
hosts.2.srvcert        <data, empty>
hosts.2.uuid           ...
hosts.size             2
gcmapping.size         0
```

   Moonlight saves hosts it discovers before they are paired. Apps are not
   saved for an unpaired host, so the `apps.N.*` shape is still unseen.
   The port now follows the address it was stored beside.

Also: the Caskroom entry in `BUNDLE_PLACES` could never match. The folder is
versioned (`moonlight/6.2.0`, not `latest`) and holds only a symlink to
`/Applications/Moonlight.app`. The cask also links `/opt/homebrew/bin/moonlight`,
which the PATH check covers. I removed it. And `npm test` failed on Node 22
before running anything (`node --test test/` looks for a module named `test`);
it is now `node --test`. 11 pass.
