### The shape

`packages/core/session.js`, `endSession()`, following your four steps:

1. Ask the host. If it is unreachable, claim nothing (`ended: null`). If it is
   free, run nothing.
2. **New here: if Moonlight's plist has no `srvcert` for that host, stop and
   say "not paired"**, pointing to the host window's Stop. Given the result
   above, waiting 25 s to learn that would be dishonest about what is already
   known.
3. Run `quit` and wait for it, with a 20 s limit.
4. Poll `/serverinfo` every 1 s, with a 25 s deadline. The answer is what the
   host says. `commandOk` is reported and decides nothing. If the host stops
   answering mid-poll, the result is `ended: null` ("unknown"), not a failure.

When the session does not end, the message names the host window's Stop
button, as you asked.

**One difference from your 0.8.1, worth taking back:** there, `tryExec` is
`execFileSync`, so the 9 s quit and every poll hold Electron's main process
and the window cannot get an answer from it for the whole wait (up to about
25 s). Here the quit and the polls are async (`execAsync` in `run.js`,
`serverInfoAsync` in `host-link.js`). The same applied to `hosts()`: it
claimed to ask hosts "in parallel", but a synchronous call inside
`Promise.all` ran them one after another. It is now actually parallel. The
Linux client's `hosts()` may have the same problem; I have not read that part.
